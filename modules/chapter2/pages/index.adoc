= The AI Revolution (AIOps, RAG, and MCP)

Ansible Automation Platform (AAP) 2.7 establishes the critical, industrial-grade connection between artificial intelligence and IT operations by acting as the trusted execution layer for the agentic AI era. By introducing "Bring-Your-Own-Knowledge" (BYOK) Retrieval-Augmented Generation (RAG) pipelines alongside the Model Context Protocol (MCP) server integration, AAP 2.7 transforms experimental AI insights into policy-driven, audited automation workflows. 
This unified framework injects organization-specific context directly into the Ansible Lightspeed Intelligent Assistant, enabling safe, natural-language orchestration across hybrid cloud environments.

== Why It Matters
- *Context-Aware AI Responses*: Generic LLMs lack internal business context. The BYOK RAG pipeline prioritizes your internal documentation and technical standards over default Ansible imagery, ensuring AI suggestions strictly adhere to your specific enterprise environment and compliance policies.
- *Universal, Zero-Custom AI Bridge*: The introduction of the standard Model Context Protocol (MCP) server removes the need for brittle, custom API integrations. It allows third-party AI agents and development tools (like Claude or Cursor) to communicate directly and safely with your automation estate via natural language.
- *End-to-End AIOps Remediation*: IT environments generate massive telemetry and alert volume. This framework closes the loop by ingesting complex event data, using AI to enrich the context and recommend resolutions, and triggering deterministic Ansible playbooks to remediate issues—all while enforcing strict human-in-the-loop approvals for corporate governance.
- *Dual-Layer Security Guardrails*: As AI moves toward autonomous, agentic action, security is paramount. The MCP server inherits AAP’s existing Role-Based Access Control (RBAC) and can be locked down in a "read-only" mode for safe infrastructure monitoring, or configured for "read-write" mode to securely launch automation jobs without exposing raw secrets.

== How Someone Actually Uses This (The Walkthrough)

To put this into practice, we would establish an integrated workflow that continuously feeds our environment's unique context directly into our automated operations. 

- *Step 1: Build your custom knowledge base.* You can now inject your own internal documentation into the assistant's Retrieval-Augmented Generation (RAG) pipeline.The system can reference a secondary RAG image/repository to answer end-user questions.
- *Step 2: Turn on the MCP Server.* The MCP integration (entering Tech Preview) enables Large Language Models (LLMs) to interact with and manage AAP through natural language. You can extend Red Hat-maintained content use cases via the MCP plugin and include MCP servers in Execution Environments.
- *Step 3: Connect the plumbing.* We connect our monitoring tools to the platform. Now, whenever an alert comes in, the AI enriches it with context, waits for our thumbs-up, and fires off the right Ansible playbook to solve the issue.
