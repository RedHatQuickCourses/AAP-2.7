= Developer and User Experience

The developer and self-service experiences have been streamlined to empower your engineering teams and provide platform administrators with significant quality-of-life updates.

image::Image 5.png[]

== Empower Platform Engineering

*Developer Tools:* This release focuses heavily on speeding up content creation and reducing context switching.

=== Visual Execution Environment Builder + Content Discovery

The *visual execution environment builder* reduces time-to-automate and ensures consistency and governance:

- *Visual authoring:* Eliminates YAML syntax errors allowing users to build consistent EEs with guided, step-by-step workflows
- *Integrated Ansible Content Collections:* Developers can quickly locate the collections they need within the builder experience
- *Governance:* Customers can add approved custom EE builder templates. Red Hat provides recommended EE templates for IT domain use cases
- *Platform experience:* Accessed directly via automation portal, making SCM and Git interactions more seamless

=== Ansible Development Workspaces [Tech Preview]

*Ansible development workspaces* include integrated development tools for content creation and testing based on best practices:

- Integrated, Ansible-specific tooling + generative AI, built on OpenShift Dev Spaces
- Simplifies creation, testing, and deployment of Ansible content
- Provides environment that is consistent and more secure—based on Ansible-recommended practices

=== MCP Server-based Assistant in Ansible VS Code Extension

The *MCP server for VS Code extension* provides:

- *AI-powered assistance* for creating, testing, and debugging automation content by exposing Ansible development tools
- Creates the foundation for *compliant-by-design* content, *context-aware linting*, and AI-assisted debugging through natural language interactions
- Boosts developer productivity and reduces context switching

Additionally, you now have a single, searchable view of Ansible collections aggregated from multiple sources (like Automation Hub and Automation Content). Furthermore, the VS Code Ansible plugin has added direct support for Google Vertex and RHEL AI models.

== *Why does it matter?*

This drastically simplifies the developer workflow by eliminating manual build configurations and command-line execution for EE images. The unified view speeds up content discovery, and adding Vertex and RHEL AI support means developers can utilize powerful AI coding assistants directly inside their IDE without being locked into a single AI provider.

== *How to use it?*

- Utilize the centralized platform UI to discover reusable content collections and trigger automated EE builds without touching the command line. For detail step to step guide https://interact.redhat.com/share/qIZHKuUp78I4yc8Vu2a9/[Automation Portal - Execution Environment Builder]
- Connect your VS Code Ansible extension directly to Google Vertex or RHEL AI to start receiving intelligent code suggestions as you write playbooks.

== Drive Automation Adoption and Scale

*Self-service Enhancements and Usability* Platform administrators and playbook authors now have powerful new ways to curate the user experience and communicate with end-users.

=== Automation Dashboard [Tech Preview]

The new *Automation dashboard* can be accessed directly within the platform UI and provides:

- *Demonstrate value and measure ROI*
- *Make smarter, data-driven decisions*
- *Optimize and right-size your automation*
- *Securely report and share your data*
- *New! Integration within the Ansible Automation Platform UI*

NOTE: Customers with multiple AAP deployments/clusters are encouraged to use the https://access.redhat.com/articles/7102421[automation dashboard utility deployment on RHEL 9/10] or integrate service with internal BI tools.

=== Self-Service Portal Enhancements

- *Direct Feedback:* Playbook authors can use *ansible.builtin.debug* messages to send URLs and guidance directly to self-service users, displaying the results right in the self-service portal logs.
- *Template Filtering:* Job Template sync filtering now supports *excludeLabels*.
- *Runtime Feature Flags:* You can now enable or disable feature flags directly from the user interface during runtime using inventory file during containerized install to integrate dashboard within platform UI.
- *Accessibility:* The unified UI now meets Web Content Accessibility Guidelines (WCAG) 2.2.

NOTE: Automation dashboard can not be enabled without metrics service. Containerized installer or operator-based deployment as part of AAP installation.

== Why does it matter?

These changes allow for dynamic platform management without reinstallations (via runtime flags), the ability to toggle features on or off enables rapid experimentation and Ansible Automation Platform’s self-service automation portal helps to make automation accessible to everyone which give admins a highly efficient way to clean up the self-service portal without maintaining complex inclusion logic. The direct feedback mechanism bridges the communication gap between automation engineers and standard users.

== How to use it?

- *To communicate with users:* Insert *ansible.builtin.debug* tasks into your playbooks with custom messages, URLs, or instructions so the self-service user sees them upon job completion.
- *To hide templates:* Apply specific AAP Labels to templates and use the *excludeLabels* filter so they automatically disappear from the automation portal.
- *To toggle features:* Navigate directly to the user interface settings to toggle feature flags on or off while the platform is running—no re-installation required.
